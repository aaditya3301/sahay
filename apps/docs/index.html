Sahay for developers

Put your business's AI sales & support agent on your own website, keep it up to date with your orders, and let it act on them, whatever your site is built with.

How it fits together

Tickets and conversations live in Sahay. Orders, products and customers live with you. Connectors join the two.

  • Every message (widget, WhatsApp, email, phone, your contact form) becomes a conversation in Sahay. Support issues become tickets (numbered per business, like LL-1042); buying chats become leads.
  • When the AI needs facts or actions it calls one fixed list of actions, the Commerce Contract. Shopify, WooCommerce and custom sites each have an adapter, so the AI never cares which platform is behind it.
  • The AI proposes, your rules decide: every action (refund, return, cancel) passes Sahay's policy check before your endpoint is called.

Connect in 3 levels

Level 1 · 5 minutes

Paste the widget. The AI answers FAQs and policies from your website, captures leads, creates tickets and collects order numbers and photos for your team.

Level 2 · ~1 hour

Sign logged-in customers and send order/product events. The AI knows who's chatting, gives live order status and sends proactive updates.

Level 3 · ~half a day

Expose one endpoint for the Commerce Contract. The AI can check live stock and do returns, exchanges and cancellations, inside your rules.

Keys & security

KeyWhereUsed for
pk_… site keyBrowser (public)Loads the widget. Works only on the domains you allow in Agent Studio → Website widget.
sk_… secret keyYour server onlySigning customers, sending events, the REST API, verifying our calls to your endpoint. Rotate it in Agent Studio.
whsec_…Your webhook receiverVerifying webhooks we send you.

Requests between our servers and yours are signed and timestamped: X-Sahay-Timestamp and X-Sahay-Signature: sha256=HMAC_SHA256(secret, "<timestamp>.<raw body>"). Reject anything older than 5 minutes. Events carry an id; sending the same id twice is ignored. Store credentials (Shopify, WooCommerce, Sarvam tokens) are encrypted at rest.

Level 2 · Identify logged-in customers

Sign the customer on your server, pass the result to the widget. Signed customers can see their orders without an OTP; anonymous visitors verify their phone inside the chat first.

import { Sahay } from '@sahay/node'
const sahay = new Sahay(process.env.SAHAY_SECRET_KEY)

app.get('/account', (req, res) => {
  const { user, userHash } = sahay.identify({ email: req.user.email, name: req.user.name })
  res.render('account', { sahayInit: { siteKey: 'pk_yourbrand_xxx', user, userHash } })
})
// browser: init(sahayInit)
from sahay import Sahay            # packages/python-sdk/sahay.py (standard library only)
sahay = Sahay(os.environ["SAHAY_SECRET_KEY"])
signed = sahay.identify(email=user.email, name=user.name)   # {"user": {...}, "userHash": "..."}
require 'Sahay.php';                 // packages/php-sdk/Sahay.php
$sahay = new Sahay(getenv('SAHAY_SECRET_KEY'));
$signed = $sahay->identify(['email' => $user->email, 'name' => $user->name]);

No SDK? userHash = HMAC_SHA256(secret_key, lowercase(email or phone)) as hex.

Level 3 · The Commerce Contract

One endpoint on your server answers these actions. Implement only what you support; anything else, the AI hands to your team.

ActionParamsReturn
getOrderorderRefOrder or null
findOrdersphone, email, limitOrder[] (newest first)
searchProductsquery, limitProduct[]
getProduct · checkStockskuProduct · { stock }
createReturnorderRef, skus, reason, type (return | exchange){ returnId, pickupDate }
cancelOrderorderRef, reason{ cancelled: true }
refundOrderorderRef, amount, reason{ refundId }
updateAddress · rescheduleDeliveryorderRef + address | date{ updated: true }
createCoupon · tagOrdervalue, customerRef · orderRef, tag{ code } · {}

Order: { orderRef, customerName, customerPhone, customerEmail, items: [{ sku, title, qty, price }], total, paymentMethod, status, courier, trackingNumber, trackingUrl, expectedDelivery, deliveredAt, placedAt }. Product: { sku, title, price, stock, category, description }. Prices in rupees.

Request: POST your-url with {"action": "getOrder", "params": {...}, "request_id": "..."} and the signature headers. Response: {"ok": true, "data": ...}, or {"ok": false, "error": "not_supported"} (404). Answer within 8 seconds (phone calls need under ~1 second; keep it fast). Machine-readable spec: commerce-contract.json.

Refunds, returns and cancellations only reach your endpoint after Sahay's policy check allows them (or a person approves). The AI can't talk its way past your rules.

Your endpoint

import express from 'express'
import { Sahay } from '@sahay/node'
const sahay = new Sahay(process.env.SAHAY_SECRET_KEY)
const app = express()

// mount BEFORE express.json(): the handler needs the raw body to check the signature
app.post('/sahay', express.text({ type: '*/*' }), sahay.handler({
  getOrder: async ({ orderRef }) => toContract(await db.orders.find(orderRef)),
  findOrders: async ({ phone, email }) => (await db.orders.byCustomer(phone, email)).map(toContract),
  checkStock: async ({ sku }) => ({ stock: await db.stock(sku) }),
  createReturn: async ({ orderRef, skus, reason, type }) => db.returns.create({ orderRef, skus, reason, type }),
}))
from fastapi import FastAPI, Request
from fastapi.responses import JSONResponse
from sahay import Sahay
sahay, app = Sahay(os.environ["SAHAY_SECRET_KEY"]), FastAPI()

@app.post("/sahay")
async def sahay_endpoint(request: Request):
    status, body = sahay.handle(await request.body(), dict(request.headers), {
        "getOrder": lambda orderRef: to_contract(get_order(orderRef)),
        "checkStock": lambda sku: {"stock": stock_of(sku)},
        "createReturn": lambda orderRef, skus, reason, type: create_return(orderRef, skus, reason, type),
    })
    return JSONResponse(body, status_code=status)
// sahay.php on your server
require 'Sahay.php';
$sahay = new Sahay(getenv('SAHAY_SECRET_KEY'));
$sahay->handle([
  'getOrder'   => fn($p) => to_contract(get_order($p['orderRef'])),
  'checkStock' => fn($p) => ['stock' => stock_of($p['sku'])],
]);

Shopify & WooCommerce

Shopify: add the app embed block (integrations/shopify) and connect the store with an Admin API token in Integrations. Orders, products, stock and abandoned checkouts come through the Shopify adapter. WooCommerce / WordPress: install the plugin (integrations/wordpress/sahay-chat.php) for the widget and paste a WooCommerce REST key (read/write) in Integrations. The AI uses the same Commerce Contract either way.

Voice agent (Sarvam)

Sarvam rents the phone number and does the listening and speaking (Hindi, Hinglish and 10 more Indian languages); Sahay stays the brain. Setup is one time per business in Agent Studio → Voice agent, which gives you the prompt, the on-start hook, one cURL per tool and the webhook URL to paste into Sarvam.

  1. Before hello: Sarvam's on-start hook calls /v1/voice/sarvam/start; we find the business and the caller and return their name, orders and open tickets as agent variables.
  2. During the call: Sarvam calls our tools (/v1/voice/sarvam/tools/get_order, …/create_return, …/send_link_whatsapp, …/transfer_to_human). Same rules as chat; each tool returns one short line to speak.
  3. After: the call webhook sends the transcript; it lands on the customer's timeline and updates the ticket.
  4. Outbound: COD confirmations and callbacks are dialed through Sarvam's outbound API.

Cost: about ₹3–3.50 per minute plus telephony; an Indian number is about ₹59 per 30 days. Browser voice calls from the widget cost nothing in telephony. Prefer your own pipeline? The same tools are available at /v1/voice/calls/* with your secret key.

How tickets work

  • One customer record per business, matched by email, phone or your customer id: a WhatsApp, an email and a call from the same person land on the same customer.
  • A new message about the same order while a ticket is open joins that ticket. A reply within 7 days of resolution reopens it.
  • States: open → AI working → resolved by AI · waiting on customer · pending approval · escalated → resolved → closed. Each ticket keeps intent, urgency, sentiment, linked orders, SLA timer and a full log of every AI step.
  • Using Freshdesk/Zendesk? Subscribe a webhook to ticket.* to mirror tickets there.

Testing

  • Sandbox: every workspace starts on the demo store (fake orders and products), so you can test the widget, events and tools before connecting your real store.
  • Integration Health (dashboard → Integrations) shows green/amber/red for widget, store, events, webhooks, WhatsApp, email, voice and automations.
  • Webhook tester: "Send test" on any webhook endpoint shows the status code we got back.
  • Customer simulator and AI mystery shoppers test the agent end to end.
